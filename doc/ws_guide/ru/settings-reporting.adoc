=== Лог

==== Внесение в лог

[cols="2,5",options="header"]
|===
|Параметр |Что делает

|*Расположение лога* / *Выбор*
|Файл ADIF, в который WS записывает ваши QSO. По умолчанию - `wsjtx_log.adi` в
папке данных WS. *Выбор* позволяет выбрать существующий файл `.adi` или задать имя нового.
После *OK* WS переключается на этот файл и перечитывает его для статуса «уже сработан».

|*Приглашение внести QSO в лог*
|Открывает частично заполненное окно *QSO в лог*, когда вы передаёте 73 или сообщение со свободным
текстом. Выключает *Записывать в лог автоматически*.

|*Op Call*
|Позывной оператора, если он отличается от позывного станции. Заносится
в поле *Оператор* записи лога.

|*Записывать в лог автоматически*
|Вносит завершённое QSO в лог без показа окна *QSO в лог*. Выключает *Приглашение
внести QSO в лог*.

|*Только для соревнований*
|С *Записывать в лог автоматически*: автоматически вносит в лог только во время соревнования
(NA VHF, EU VHF, WW Digi, ARRL Digi, Field Day, RTTY Roundup).
Для остальных QSO открывается окно *QSO в лог*. QSO в роли Fox всегда вносятся в лог автоматически.

|*Заполнять отсутствующие локаторы 'ZZ00'*
|Записывает `ZZ00` в качестве локатора, если другая станция его не передала.

|*Записывать 4-символьные локаторы*
|Сокращает в логе 6-символьные локаторы до 4 символов.

|*Записывать частоту трансивера вместо частоты Tx*
|Записывает в лог частоту трансивера. Если флажок снят, WS записывает частоту трансивера плюс
ваше звуковое смещение Tx.

|*Преобразовать моду в RTTY*
|Записывает QSO в JT9 как режим RTTY для программ ведения лога, которые не знают JT9.

|*Добавить рапорта дБ в комментарии*
|Записывает в поле *Комментарии* вид связи и переданный и принятый рапорты
(например, `FT8  Sent: -10  Rcvd: -12`) для программ ведения лога, которые не принимают эти
рапорты.

|*Особый вид активности в комментарии*
|Записывает активный особый вид активности в поле *Комментарии*, например
"EU VHF Contest" или "F/H mode". При собственном названии соревнования, например
PACC, используется "PACC Contest". Не применяется, если включено *Добавить рапорта дБ в комментарии*
или комментарий сохранён в окне *QSO в лог*.
|===

TIP: Отправка в Cloudlog или Wavelog настраивается на вкладке *Расш.*.

==== PSK Reporter

[cols="2,5",options="header"]
|===
|Параметр |Что делает

|*Отправлять споты на сервер PSK Reporter*
|Отправляет данные вашей станции и декодированные вами станции на
https://pskreporter.info[PSK Reporter]. Описание антенны берётся из
*Информация о станции* на вкладке *Частоты* для текущего диапазона.
Декодирования из записанных файлов не отправляются.

|*Использовать соединение TCP/IP*
|Использует TCP вместо UDP. Нужно, только если ваши UDP-отчёты теряются по пути.
|===

==== LiveCQ

LiveCQ - веб-сервис, который показывает текущую активность в Q65 (и VHF JT65) и
то, кто кого слышит.

[cols="2,5",options="header"]
|===
|Параметр |Что делает

|*Включить Q65 LiveCQ*
|Главный выключатель (по умолчанию включён). Отправляет ваши декодирования Q65, а также декодирования JT65
на 50 МГц и выше, по отмеченным ниже адресам. В Q65 также
получает зелёные галочки «кто меня слышал».

|*W3SZ (w3sz.com)* и название программы
|Отправляет в LiveCQ W3SZ только сообщения типа CQ - те же отчёты, что туда отправляют WS-MAP и
EME65. Выпадающий список выбирает передаваемое название программы:
*WSJTX* (как до переименования) или *WS*.

|*N6NU (livecq.n6nu.org)*
|Полный адрес (по умолчанию включён): CQ и адресованные сообщения. Это источник
зелёных галочек; он необходим для работы в режиме *Q65 Pileup* (вкладка *Расш.*).

|*Свой:* и URL
|Отправляет только сообщения типа CQ на ваш собственный сервер LiveCQ, например
`\http://localhost:3000/api/livecq_update`. Ничего не делает, пока URL пуст.
Если *N6NU* выключен, зелёные галочки запрашиваются с этого сервера.
|===

NOTE: Декодирования из записанных файлов отправляются только на сервер N6NU с пометкой,
по которой сайт по умолчанию их скрывает.

==== UDP-сервер

WS передаёт своё состояние, декодирования и внесённые в лог QSO по UDP сопутствующим программам,
например JTAlert или GridTracker.

[cols="2,5",options="header"]
|===
|Параметр |Что делает

|*UDP-сервер*
|Адрес принимающей программы, обычно `127.0.0.1` (по умолчанию). С
адресом группы многоадресной рассылки (например, `239.255.0.1`) одновременно могут слушать несколько программ.
Только адреса IPv4.

|*Номер порта UDP сервера*
|Порт принимающей программы, по умолчанию 2237. 0 = UDP-сообщения не отправляются.

|*Исходящие интерфейсы* / *Многоадресный TTL*
|Показываются только для многоадресного адреса. Для программ на том же компьютере
достаточно петлевого интерфейса. Оставьте TTL равным 1, чтобы трафик не выходил за пределы
вашей локальной сети.

|*Разрешить принимать UDP-запросы*
|Позволяет сопутствующей программе управлять WS, например начать QSO со станцией, по которой вы
щёлкнули в ней. Если флажок снят, запросы игнорируются.

|*Уведомить о получении UDP запроса*
|Выводит окно WS на передний план, когда запрос принят. Результат
зависит от операционной системы.

|*Восстановить окно при получении UDP запроса*
|Восстанавливает свёрнутое окно WS, когда запрос принят.

|*Режим совместимости с WSJT-X*
|WS представляется как "WSJT-X" вместо "WS" (например, "WSJT-X - rig") для
программ, которые распознают только WSJT-X. Действует сразу.
|===

==== Дополнительный UDP-сервер

[cols="2,5",options="header"]
|===
|Параметр |Что делает

|*Разрешить передачу данных QSO в ADIF формате*
|Отправляет каждое внесённое в лог QSO записью ADIF по UDP, например в N1MM Logger+.

|*Имя сервера или IP-адрес*
|Адрес принимающей программы, обычно `127.0.0.1`.

|*Номер порта сервера*
|UDP-порт принимающей программы; 2333 для N1MM Logger+ (по умолчанию).
0 = ничего не отправляется.
|===
