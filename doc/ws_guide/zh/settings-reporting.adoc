==== 记录日志

[cols="2,5",options="header"]
|===
|设置 |功能

|**通联日志位置** / **选择**
|WS 写入 QSO 的 ADIF 文件。默认为 WS 数据目录中的 `wsjtx_log.adi`。
**选择** 可选取现有的 `.adi` 文件或命名一个新文件。
点击 **确定** 后，WS 切换到该文件并重新读取，以获取曾经通联状态。

|**提示我记录通联日志**
|发送 73 或自由文本信息时，打开已部分填写的 **记录通联** 窗口。
会关闭 **日志自动记录**。

|**操作员呼号**
|操作员的呼号（如果与电台呼号不同）。它会写入
日志条目的 **操作员** 字段。

|**日志自动记录**
|记录完成的 QSO 而不显示 **记录通联** 窗口。会关闭 **提示我记录通联日志**。

|**仅竞赛**
|配合 **日志自动记录**：只在竞赛
活动（NA VHF、EU VHF、WW Digi、ARRL Digi、Field Day、RTTY Roundup）期间自动记录。
其他 QSO 会打开 **记录通联** 窗口。狐狸 QSO 始终自动记录。

|**用 'ZZ00' 填充缺失的网格**
|对方未发送网格时，以 `ZZ00` 记录网格。

|**记录4位数网格**
|在日志中将 6 字符定位符缩短为 4 字符。

|**记录显示频率而非 Tx 频率**
|记录电台的显示频率。不勾选时，WS 记录显示频率加上
你的发射音频偏移。

|**把日志记录转成 RTTY 模式**
|将 JT9 QSO 以 RTTY 模式记录，供不认识 JT9 的日志程序使用。

|**把 dB 信号报告写入注释栏**
|将模式以及发送和接收的信号报告写入 **注释**
（例如 `FT8  Sent: -10  Rcvd: -12`），供拒收这些
报告的日志程序使用。

|**特殊操作活动注释**
|将当前启用的特殊操作活动写入 **注释**，例如
"EU VHF Contest" 或 "F/H mode"。使用单独竞赛名称（如
PACC）时，写入 "PACC Contest"。当 **把 dB 信号报告写入注释栏**
开启，或注释在 **记录通联** 窗口中被保留时，不适用。
|===

TIP: 上传到 Cloudlog 或 Wavelog 在 **进阶设置** 选项卡上设置。

==== PSK Reporter

[cols="2,5",options="header"]
|===
|设置 |功能

|**启用 PSK Reporter 发报**
|将你的电台信息以及你解码到的电台发送到
https://pskreporter.info[PSK Reporter]。天线文本取自
**频率** 选项卡上当前波段的 **电台信息**。
来自录音文件的解码不会上报。

|**使用 TCP/IP 连接**
|使用 TCP 代替 UDP。只有在 UDP 报告途中丢失时才需要。
|===

==== LiveCQ

LiveCQ 是一项网络服务，列出实时的 Q65（和 VHF JT65）活动，
并显示谁听到了谁。

[cols="2,5",options="header"]
|===
|设置 |功能

|**启用 Q65 LiveCQ**
|总开关（默认开启）。将你的 Q65 解码以及 50 MHz 及以上的 JT65
解码上传到下面勾选的目的地。在 Q65 中，它还会
获取 "谁听到了我" 的绿色勾号。

|**W3SZ (w3sz.com)** 和程序名称
|只向 W3SZ LiveCQ 发送 CQ 类信息，与 WS-MAP 和
EME65 发往该处的报告相同。下拉列表选择上报的程序名称：
**WSJTX**（与更名前相同）或 **WS**。

|**N6NU (livecq.n6nu.org)**
|完整目的地（默认开启）：CQ 和定向信息。它是
绿色勾号的来源，也是 **Q65 堆叠** 操作（**进阶设置** 选项卡）所必需的。

|**自定义:** 和 URL
|只向你自己的 LiveCQ 服务器发送 CQ 类信息，例如
`\http://localhost:3000/api/livecq_update`。URL 为空时不执行任何操作。
关闭 **N6NU** 时，从该服务器获取绿色勾号。
|===

NOTE: 来自录音文件的解码只发送到 N6NU 服务器，并带有标记，
网站默认隐藏它们。

==== UDP服务器

WS 通过 UDP 将其状态、解码和已记录的 QSO 发送给
JTAlert 或 GridTracker 等配套程序。

[cols="2,5",options="header"]
|===
|设置 |功能

|**主要UDP服务器**
|接收程序的地址，通常为 `127.0.0.1`（默认）。使用
多播组地址（例如 `239.255.0.1`）时，多个程序可以
同时监听。仅支持 IPv4 地址。

|**主要UDP服务器端口**
|接收程序的端口，默认为 2237。0 = 不发送 UDP 信息。

|**传出接口** / **多播 TTL**
|仅在使用多播地址时显示。对于同一台计算机上的程序，
环回接口即可。请将 TTL 保持为 1，使流量留在你的
本地网络中。

|**接受 UDP 请求**
|允许配套程序控制 WS，例如与你在该程序中点击的电台
开始 QSO。不勾选时忽略请求。

|**在接受UDP的请求时通知**
|接受请求时将 WS 窗口置于前台。效果
取决于操作系统。

|**接受UDP请求还原窗口**
|接受请求时还原最小化的 WS 窗口。

|**WSJT-X 兼容模式**
|将 WS 标识为 "WSJT-X" 而不是 "WS"（例如 "WSJT-X - rig"），供
只识别 WSJT-X 的程序使用。立即生效。
|===

==== 次要UDP服务器

[cols="2,5",options="header"]
|===
|设置 |功能

|**启用 ADIF 记录广播**
|将每个已记录的 QSO 作为 ADIF 记录通过 UDP 发送，例如发给 N1MM Logger+。

|**服务器名称或 IP 地址**
|接收程序的地址，通常为 `127.0.0.1`。

|**服务器端口**
|接收程序的 UDP 端口；N1MM Logger+ 为 2333（默认）。
0 = 不发送任何内容。
|===
