==== 記錄日誌

[cols="2,5",options="header"]
|===
|設定 |功能

|**日誌位置** / **選擇**
|WS 寫入 QSO 的 ADIF 檔案。預設為 WS 資料目錄中的 `wsjtx_log.adi`。
**選擇**可挑選現有的 `.adi` 檔案或為新檔案命名。
按**確定**後，WS 會切換到該檔案，並重新讀取以取得曾經通聯狀態。

|**提示我記錄通聯日誌**
|當您發送 73 或自由文字訊息時，開啟已部分填好的**記錄通聯**視窗。
會關閉**日誌自動記錄**。

|**操作員呼號**
|操作員的呼號（若與電臺呼號不同）。它會寫入
日誌項目的**操作員**欄位。

|**日誌自動記錄**
|記錄已完成的 QSO，而不顯示**記錄通聯**視窗。會關閉
**提示我記錄通聯日誌**。

|**僅競賽**
|搭配**日誌自動記錄**：只在競賽活動期間自動記錄
（NA VHF、EU VHF、WW Digi、ARRL Digi、Field Day、RTTY Roundup）。
其他 QSO 會開啟**記錄通聯**視窗。狐狸 QSO 一律自動記錄。

|**用 'ZZ00' 填充缺失的網格**
|對方電臺未發送網格時，以 `ZZ00` 作為網格記錄。

|**記錄4位數網格**
|在日誌中將 6 個字元的網格座標縮短為 4 個字元。

|**記錄撥號頻率而非 Tx 頻率**
|記錄電臺的刻度頻率。未勾選時，WS 記錄刻度頻率加上
您的發射音頻偏移。

|**把日誌紀錄轉成 RTTY 模式**
|將 JT9 QSO 記錄為 RTTY 模式，供不認得 JT9 的日誌程式使用。

|**把 dB 訊號報告寫入備註欄**
|將模式與發送、接收的報告寫入**備註**
（例如 `FT8  Sent: -10  Rcvd: -12`），供會拒收這些
報告的日誌程式使用。

|**特殊操作活動備註**
|將目前啟用的特殊操作活動寫入**備註**，例如
「EU VHF Contest」或「F/H mode」。使用 PACC 這類單獨競賽名稱時，
則寫入「PACC Contest」。若**把 dB 訊號報告寫入備註欄**已開啟，
或備註在**記錄通聯**視窗中被保留，則不套用。
|===

TIP: 上傳到 Cloudlog 或 Wavelog 的設定位於**進階設定**分頁。

==== PSK Reporter

[cols="2,5",options="header"]
|===
|設定 |功能

|**啟用 PSK Reporter 發報**
|將您的電臺資料與您解碼到的電臺傳送到
https://pskreporter.info[PSK Reporter]。天線文字取自
**頻率**分頁中目前波段的**電臺相關資料**。
來自錄音檔的解碼不會回報。

|**使用 TCP/IP 連接**
|使用 TCP 而非 UDP。只有在您的 UDP 回報在傳送途中遺失時才需要。
|===

==== LiveCQ

LiveCQ 是一項網路服務，列出即時的 Q65（以及 VHF JT65）活動，
並顯示誰聽到了誰。

[cols="2,5",options="header"]
|===
|設定 |功能

|**啟用 Q65 LiveCQ**
|總開關（預設開啟）。將您的 Q65 解碼，以及 50 MHz 以上的 JT65
解碼，上傳到下方勾選的目的地。在 Q65 中也會
取得「誰聽到了我」的綠色勾號。

|**W3SZ (w3sz.com)** 與程式名稱
|只將 CQ 類訊息傳送到 W3SZ LiveCQ，與 WS-MAP 和
EME65 傳送到那裡的回報相同。下拉清單選擇回報的程式名稱：
**WSJTX**（與更名前相同）或 **WS**。

|**N6NU (livecq.n6nu.org)**
|完整目的地（預設開啟）：CQ 與指定對象的訊息。它是
綠色勾號的來源，也是 **Q65 堆叠**操作（**進階設定**分頁）的必要條件。

|**自訂:** 與 URL
|只將 CQ 類訊息傳送到您自己的 LiveCQ 伺服器，例如
`\http://localhost:3000/api/livecq_update`。URL 為空時不會有任何動作。
**N6NU** 關閉時，綠色勾號會從此伺服器取得。
|===

NOTE: 來自錄音檔的解碼只會傳送到 N6NU 伺服器，並加上標記，
讓網站預設將其隱藏。

==== UDP 伺服器

WS 會透過 UDP 將其狀態、解碼與已記錄的 QSO 傳送給 JTAlert 或 GridTracker 等
輔助程式。

[cols="2,5",options="header"]
|===
|設定 |功能

|**主要UDP伺服器**
|接收程式的位址，通常為 `127.0.0.1`（預設）。使用
群播（multicast）群組位址（例如 `239.255.0.1`）時，多個程式可以
同時監聽。僅支援 IPv4 位址。

|**主要UDP伺服器埠號**
|接收程式的埠號，預設為 2237。0 = 不傳送 UDP 訊息。

|**傳出界面** / **組播 TTL**
|只有使用群播位址時才會顯示。程式位於同一部電腦時，
使用回送（loop-back）介面即可。請將 TTL 保持為 1，讓流量留在您的
區域網路內。

|**接受 UDP 請求**
|允許輔助程式控制 WS，例如與您在該程式中點擊的電臺
開始 QSO。未勾選時，請求會被忽略。

|**在接受UDP的請求時通知**
|接受請求時，將 WS 視窗移到最前方。實際效果
取決於作業系統。

|**接受UDP請求還原視窗**
|接受請求時，還原已最小化的 WS 視窗。

|**WSJT-X 相容模式**
|將 WS 識別為「WSJT-X」而非「WS」（例如「WSJT-X - rig」），供
只認得 WSJT-X 的程式使用。立即生效。
|===

==== 次要 UDP 伺服器

[cols="2,5",options="header"]
|===
|設定 |功能

|**啟用 ADIF 記錄廣播**
|將每筆已記錄的 QSO 以 ADIF 記錄透過 UDP 傳送，例如傳給 N1MM Logger+。

|**伺服器名稱或 IP 位址**
|接收程式的位址，通常為 `127.0.0.1`。

|**伺服器埠號**
|接收程式的 UDP 埠號；N1MM Logger+ 為 2333（預設）。
0 = 不傳送任何內容。
|===
